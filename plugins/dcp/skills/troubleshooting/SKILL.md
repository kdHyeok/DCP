# DCP 트러블슈팅 기록

해결한 문제 중 다시 참고할 가치가 있는 것을 문서로 남긴다. 문서와 질문은 사용자의 언어로 쓴다.
이 절차는 사용자의 작업 요청을 대체하지 않는다. 문제 해결과 검증을 먼저 마친다.

## 시작 조건

- 사용자가 맡긴 작업 중 문제의 원인을 확정하고 해결을 검증했을 때만 판단한다. 조사 중에는 묻지 않는다. 검증이 실패했으면 "해결"로 기록하지 않는다.
- 사용자가 문제 해결을 맡기지 않은 조사나 질문 답변은 대상이 아니다. 사용자가 직접 기록을 요청하면 따른다.
- "이번엔 기록 안 해"는 현재 건만 건너뛴다. "트러블슈팅 기록 꺼줘"는 이 기능만 끄고, 다시 켜 달라고 할 때까지 묻지 않는다.

## 진행 중에 남길 것

문제를 다루는 동안 시도할 때마다 가설, 변경, 결과(로그·수치)를 대화에 한두 줄로 남긴다. 긴 세션에서 대화가 요약돼도 시도 순서를 되살릴 수 있게 하기 위해서다.

## 기록할지 판단

기록한다:

- 가설을 2개 이상 확인했거나 여러 단계를 거쳐 원인을 찾은 문제
- 해결 시도가 2번 이상 필요했던 문제
- 테스트·검사·규칙 같은 예방책으로 막을 수 있었던 오류
- 전후 측정값이 있는 성능 개선
- 환경·버전·호환성 문제

기록하지 않는다:

- 오타, import 누락처럼 첫 시도에 바로 풀리고 배울 점이 없는 것
- 요구 변경에 따른 수정
- 원인을 확정하지 못한 우회. 대신 "미해결"로 한 줄 보고한다.
- 측정값 없는 성능 개선

기록하지 않을 때는 따로 언급하지 않는다. 같은 원인의 문서가 `docs/troubleshooting/`에 이미 있으면 새로 쓰지 않고, 그 문서에 "재발" 절을 덧붙이자고 제안한다.

## 묻기

- 기록 대상이면 기록할 만한 이유를 한 줄로 알리고 "기록 / 건너뛰기"를 묻는다. 선택지 도구(예: AskUserQuestion)가 있으면 쓰고, 없으면 번호 목록으로 묻는다.
- 개념 학습 질문과 같은 때에 묻게 되면 한 번의 선택지에 함께 묻는다.
- 사용자가 "기록"을 고른 경우에만 파일을 쓴다.

## 작성

- 위치: 작업 중인 프로젝트의 `docs/troubleshooting/YYYY-MM-DD-주제.md`. 폴더가 없으면 만든다.
- 훅이 알려 준 템플릿 파일을 읽고 그 구조를 따른다.
- 관찰한 로그·수치·오류 원문만 적는다. 시도는 실제 순서대로 적고 실패한 시도도 포함한다. 측정하지 않은 값은 "미측정"으로 적는다.
- 원인 파악 흐름도와 원인 동작 그림을 Mermaid로 각각 하나 이상 넣는다. 코드는 관련 부분 발췌와 diff만 넣는다.
- 토큰, 비밀번호, 개인 정보, 사용자 이름이 든 경로는 가린다.
- "관련 CS 개념"에는 이번 수정에서 뽑은 개념 학습 후보를 적는다.
- 쓰기가 실패하면 기록했다고 말하지 않는다. 커밋은 사용자가 요청할 때만 한다.
